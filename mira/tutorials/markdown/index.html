Markdown reference

The marks this site actually renders. Headings, lists, tables, fences, footnotes, and what to leave out.

A post is a text file with a few marks in it. The marks become headings, lists, links, and code. You can read the file without a preview and still know what it says. That is the point.

The fences on this page are highlighted. Name the language on the first line of the fence and Shiki colors it. Leave the name off and the block stays plain.

Text

**bold**
*italic*
***bold italic***
~~gone~~
`code`

bold italic bold italic gone code

Use bold for a name or a label, not for a whole sentence. Italic is for a title or a word you would stress out loud. If everything is bold, nothing is.

Headings

One # per level. Do not skip. A screen reader walks the headings in order, and so does a person skimming.

## Section
### Subsection
#### A small label, when you need one

# is the page title. This page already has one, in the template, so the file starts at ##. A second # gives you two page titles.

A bullet list is for things that have no order. A numbered list is for steps. A task list is for a checklist you mean to finish. Blank line before the list, or some renderers glue it to the paragraph above.

The words in the brackets are what a person reads, and what a screen reader says. "Click here" says nothing. The address is the page you mean.

The text in an image mark is the alt text. Say what is in the picture. "Image" and "banner" are not descriptions. The portrait on the home page is "Mira, red hair in a ponytail, black jacket, pointing." A decorative line can take an empty alt, ![](rule.png), and then a screen reader skips it.

The dashes under the header are what makes it a table. Three dashes are enough. Use :--- , :---: , and ---: when a column should sit left, center, or right. Most tables do not need it.

Keep tables narrow. Four columns is a lot on a phone. A list is the better shape when each row is a sentence.

Footnotes

The feed is linked from the home page.[^feed]

[^feed]: /feed.xml

The feed is linked from the home page.1

The mark is [^name] in the sentence. The note is [^name]: on its own line, usually at the end of the file. The name can be a word. It does not have to be a number.

A file on this blog

A post lives at content/posts/<slug>.mdx. The file starts with YAML, then the words.

---
title: The lab is open
description: The first paragraph a stranger can use.
date: 2026-10-26
tags: [lab]
---

The first paragraph is the one the index can quote. Write it as a sentence a stranger can use.

.mdx is Markdown that can also hold a component. Most posts never need one. Stay in Markdown until the words cannot do the job.

What this site leaves plain

==highlight== is a GitHub extra. Leave it out. Write the word in bold, or write a sentence.

GitHub callouts (> [!NOTE]) stay as a normal quote here. If the note matters, write it as a sentence under the quote.

Raw HTML works in spots and fails in others. Prefer the marks above. They travel to GitHub, to the feed, and to a file you open in ten years.

Before you publish

  • The headings step down one at a time.
  • Every image has alt text that says what is in the picture.
  • Every fence names a language, and the preview shows color.
  • Links have words. The address is in the parentheses.
  • You opened the page on a phone width and the table still fits, or you turned it into a list.
